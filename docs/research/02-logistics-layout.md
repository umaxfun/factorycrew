# 02 — Logistics layout solvers (balancers, routing, rails, beacons, solar, city blocks)

Scope: community projects that solve logistics-layout sub-problems Kira will face when placing ghosts: belt balancers, belt/pipe routing (incl. undergrounds), rail/station templates, beacon placement, solar/accumulator fields, city-block grids. Kira constraints: Python stdlib only (sandboxed), reads live save via Lua, mods like Nullius (non-vanilla entity names, belt speeds, underground lengths), Factorio 2.0 (16-way directions, new rails, quality).

Metadata (stars / license / last push) from the GitHub REST API, 2026-10-28. "2.0?" = whether the project targets Factorio 2.0. "Mod-aware" = reads prototypes/entity data instead of hardcoding vanilla names.

Reuse verdict key: port-algorithm (reimplement idea in stdlib Python), vendor-code (copy files; license permits), call-as-is (run offline / out of sandbox, consume output), idea-only, skip.

Kira-specific note: 1.x blueprint strings use 8-way directions (0/2/4/6); 2.0 uses 16-way (0/4/8/12). The in-game importer converts automatically, but if Kira decodes a 1.x book in Python and places ghosts via `surface.create_entity`, she must double every direction and remap `transport-belt`/`underground-belt`/`splitter` (+`fast-`/`express-`) to the save's tier names (Nullius uses its own belt prototypes). For underground-heavy "narrow" designs, only use a book whose tier underground reach is ≤ the target tier's `max_underground_distance`.

## Gaps (searched, nothing worth reusing)

- **Main-bus generators**: no maintained bus-layout generator on GitHub or the mod portal (keyword scan of all 24,380 portal mods via the `api/mods?page_size=max` dump; GitHub repo search). Bus = ParallelBeltBuilder-style N-lane polyline + balancer/splitter taps from the balancer book.
- **Exact beacon-layout optimizers**: only demipixel's 2018 NEAT toy. Use templates plus OilOutpostPlanner's greedy placer.
- **2.0 rail auto-routers (A* over the new rail grid)**: none found; Railwright gives verified fixed geometry. For long-haul track, drive the engine's own rail planner rather than computing curves in Python.

## Best picks for Kira

1. **[OilOutpostPlanner](https://github.com/Coppermine-factorio/OilOutpostPlanner) (MIT): port the Steiner-tree joiner and the greedy beacon placer.** Reimplement `SolveSteinerTree` (parallel BFS from every target until two meet, join them, merge, repeat) in stdlib Python over Kira's occupancy grid. Use it for pipe networks, with runs ≥ min reach turned into pipe-to-ground, and for power-pole networks (adjacency = `wire_reach`, coverage = `supply_distance`). Port `FindBeaconLocations` with Lua feeding `beacon.profile`, `get_supply_area_distance(quality)` and the beacon size from prototypes. That makes it Nullius- and quality-aware without hardcoding anything.
2. **[auto-belt](https://github.com/Johk3/auto-belt) (GPL-3.0, clean-room port) plus [BeltRouter](https://github.com/Seancheey/FactorioBeltRouter)'s legality rules: Kira's belt router.** Lua exports a 1-byte-per-tile cell mask per chunk. Python runs HPA* over chunk regions, then `heapq` A* over (tile, heading) states, where an underground jump of length k ≤ `related_underground_belt.max_underground_distance` is a single move. Copy BeltRouter's `testCanPlace` rules: no crossing a parallel same-tier underground pair, and no pipe-to-ground facing the path. Penalise turns, search from the sink backwards, and cap the work budget. [Buildasaurus `a_star_factorio.py`](https://github.com/Buildasaurus/Factorio-Blueprint-Generator/blob/main/server/a_star_factorio.py) (MIT, stdlib) is a ready Python scaffold.
