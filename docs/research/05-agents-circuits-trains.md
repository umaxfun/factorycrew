# 05 — AI agents, circuit logic, train/station automation (prior art for Kira)

Scope: what existing Factorio community projects already solved that Kira (LLM companion, Lua read of live save, stdlib-only Python compute, ghost-only placement, consent before touching existing entities, planned "do it like there" logic copy) can borrow.

Method: GitHub repo API (`gh api repos/...`) for license/stars/last push, README and source files read via `gh api .../contents` or raw.githubusercontent.com, arXiv export API for papers, mods.factorio.com API for mods. Data as of 2026-10-28. "Last push" = repo `pushed_at`. Stars are point-in-time.

Reuse verdict legend: port = re-implement the logic in our Lua/Python; vendor = copy files in (license permitting); call-as-is = run their tool/mod unchanged next to Kira; idea-only = design inspiration; skip = not useful.

### FLE tool set (from `fle/env/tools/agent/`)

`can_place_entity, connect_entities, craft_item, extract_item, get_connection_amount, get_entities, get_entity, get_prototype_recipe, get_research_progress, get_resource_patch, harvest_resource, insert_item, inspect_inventory, launch_rocket, move_to, nearest, nearest_buildable, pickup_entity, place_entity, place_entity_next_to, print, rotate_entity, score, send_message, set_entity_recipe, set_research, shift_entity, sleep`. Admin tools (`fle/env/tools/admin/`) include `save_blueprint / load_blueprint`, `save_entity_state / load_entity_state`, `inspect_entities`, `get_path / request_path`, `render`, `get_production_stats`.

FLE MCP server (`fle/env/protocols/_mcp/tools.py`, `version_control.py`): `execute(code)`, `render(center_x, center_y)` → image, `reconnect`, plus game-state version control `commit(tag, message)`, `restore(ref)`, `undo()`, `view_history`, `list_tags`, `view_code`. Resources `fle://server/{id}/entities/{x1}/{y1}/{x2}/{y2}`, `fle://recipes`.

Helpers worth copying:
- `connect_entities(src, dst, *waypoints, connection_type={Prototype.TransportBelt, Prototype.UndergroundBelt})` — sources/targets can be positions, entities or entity groups; handles pathing, rotation, network grouping and item-count checks. Split into `resolvers/{transport,fluid,power}_connection_resolver.py` that turn an entity into the right connection point (`connect_entities/agent.md`). For Kira the same call should emit ghosts and return a bill of materials instead of spending inventory.
- `place_entity_next_to(entity, reference_position, direction, spacing)` — placement relative to another entity's footprint (`place_entity_next_to/agent.md`). Cuts off-by-one errors with multi-tile entities.
- `nearest_buildable(prototype, building_box, center)` — find a free rectangle. Kira needs this for "where should the copy go".
- `save_entity_state / load_entity_state` and MCP `commit/restore/undo` — snapshot + rollback. Maps directly onto Kira's consent flow: snapshot the area before an approved change, offer one-click undo.
- `agent.md` per tool: the LLM-facing doc lives next to the implementation and is concatenated into the system prompt. Cheap and keeps docs honest.

### What helps LLMs most (cross-project, cited)

- High-level, intent-shaped tools beat primitive ones. khoyga007 reduced the surface to 3 tools (`observe/achieve/report`) with an in-game executor; FLE gives `connect_entities`; linsyking has `route_belt` and `build_plan`. sbarisic's ~40 primitives are the counter-example.
- Dry-run + read-back. linsyking's `build_plan dry_run` reports dead-end belt corners, belts facing each other, inserters facing the wrong way, drills with no receiver. khoyga007 LESSONS #6: "Read the ground back after every write; the return value lies" (re-placed ghosts lost underground in/out type and inserter filters). This matters for "do it like there": verify the copy by diffing settings after placement.
- Fix ambiguous conventions in the API. linsyking: inserter direction is the side it *picks up from*, so expose `drop_to`/`pickup_from` instead; directions are 16-way in 2.0 (0=N, 4=E, 8=S, 12=W).
- Push events to the model. linsyking appends job results, chat and an `ALERTS:` delta to every tool result so the agent never polls.
- Measure flow, don't infer from stock. khoyga007 LESSONS #3 ("Plan by numbers, measure by flow"); linsyking `measure_belt`; FLE `get_production_stats`.
- Shared-resource awareness. khoyga007 LESSONS #7: every new consumer on a shared belt/fluid segment steals from someone. Relevant when Kira wires a copied station into an existing circuit network.
- Human-in-the-loop for irreversible moments. khoyga007 LESSONS #16: say where to look and wait for "go".

Native API that matters more than any compiler (verified in [runtime-api.json](https://lua-api.factorio.com/latest/runtime-api.json), API version 2.1.24):
- `LuaItemCommon.create_blueprint{surface, force, area, include_entities, include_modules, include_station_names, include_trains, include_fuel, always_include_tiles}` grabs an area into a blueprint, including control behaviour and wires. Use a script inventory, not the player's cursor.
- `LuaItemCommon.get_blueprint_entities()` → plain Lua tables (`control_behavior`, `wires`, `name`, `position`, `direction`, `tags`, schedules for included locomotives). Easy to serialise to JSON for the Python side.
- `LuaItemCommon.build_blueprint{surface, force, position, direction, build_mode, by_player, raise_built, skip_fog_of_war}` places the result as ghosts, so Kira's ghost-only rule holds.
- `LuaEntity.copy_settings(entity, by_player)` = Shift+RMB/LMB "paste settings" from one existing entity to another. This is the consent-gated path for "make *this existing* stop behave like that one".
- `LuaEntity.get_wire_connector(id, or_create)` is the 2.0 wire model. It replaces 1.1 `connect_neighbour`.
- Blueprint string codec is `"0" + base64(zlib(json))`. Pure stdlib (`base64`, `zlib`, `json`), so the Python side can read and write strings without Draftsman.

Notes on how stations are standardised (2.0):
- Vanilla: a stop name template (often with rich-text item icons) + generic interrupts + circuit-set train limit/priority + a constant/decider block reading the buffer chests. The logic is spread across the train stop's `control_behavior`, the combinators wired to it, and the *train group's* interrupts. The interrupts are not on the stop. A full copy therefore needs both the area blueprint and `LuaSchedule.get_interrupts()` of a train serving it.
- LTN/CS1: logic is concentrated in one combinator next to the stop, so blueprints copy it cleanly. The mods re-register stations from built events and blueprint tags.
- Modded entities that keep settings in mod storage (not in control behaviour) only survive copies if the mod writes them into blueprint `tags` (CS1 does, through `combinator_build_init(..., tags)`). Kira should check `tags` on source entities and warn when a modded entity has none.

## Best picks for Kira

1. Native blueprint round-trip as the "do it like there" engine (call-as-is: Factorio Lua API). In Lua, `create_blueprint{area=source_bbox, include_station_names=true, include_trains=false}` into a script inventory, then `get_blueprint_entities()`, plus `LuaTrain.get_schedule()` → `get_records()/get_interrupts()/group` for one train that serves the source stop. Ship it to Python as JSON. In Python (stdlib), normalise to the source's anchor (the train stop), rotate/mirror to the target's rail direction (2.0 has 16-way directions), rewrite stop names by template (e.g. replace the item icon `[item=iron-plate]` → `[item=copper-plate]` and the signals in constant-combinator sections), and keep wires as entity-index pairs. Back in Lua, `set_blueprint_entities` + `build_blueprint{build_mode=..., raise_built=true}` at the target as ghosts. Then read back and diff every `control_behavior` against the source (khoyga007 LESSONS #6). Interrupts are proposed as a separate consent step ("add interrupt X to group Y"), because they change trains that already exist.
2. FLE tool-triple + helpers (port, MIT). Copy the `client.py` / `server.lua` / `agent.md` per-tool layout so each Kira tool's LLM doc sits next to its code. Port `place_entity_next_to`, `nearest_buildable` (where to put the copy) and the `connect_entities` resolver split (transport/fluid/power) as ghost-emitting planners that return a bill of materials. Port the MCP `commit/restore/undo` idea as "snapshot area before approved change → one-click undo", which is exactly what the consent flow needs.
3. linsyking/factorio-mcp conventions (port, MIT; avoid the GPL `scripts/route/` dir). Dry-run every plan with its belt/inserter sanity checks, use `drop_to`/`pickup_from` instead of raw inserter direction, append an `ALERTS:`/news footer to every tool result, `trace_belt`/`measure_belt` for "is the copy working". Its `route_belt` design (weighted A* over (tile,direction), forced-ghost legality check) is the model for connecting a copied station to existing rails/belts. Write our own code from the description.
4. Station-logic recognisers for LTN / Cybersyn 1 / vanilla-generic-interrupt (port small readers).
