# 01 — Resource outpost planners (ore drills, pumpjacks, water, Space Age)

Survey of community tools that lay out mining outposts, for reuse in Kira (Lua reads save → stdlib-only Python computes layout → Lua places ghosts). All URLs, licenses, stars and last-push dates were checked on 2026-10-28 via `gh api repos/...` and the mods.factorio.com API; algorithm notes cite the source file that was actually read. "Mod-aware" = reads drill/pole/pipe/beacon geometry from `prototypes.*` at runtime rather than hardcoding vanilla names.

Space Age resources (big-mining-drill 5×5 with a larger radius, Fulgora scrap, Vulcanus tungsten/lava, Aquilo heat pipes) are covered generically by MPP (drill geometry from prototypes) and by P.U.M.P. / Oil Outpost Planner (any fluid `resource_category`, heat pipes, foundation tiles).

## Best picks for Kira

All three game-API mods (MPP, P.U.M.P., Oil Outpost Planner) split cleanly into "read prototypes" (Lua) and "pure grid algorithm". That is exactly Kira's Lua → Python → Lua split. Kira's Lua side should export one generic geometry record per chosen entity and let Python stay name-agnostic. That record covers drill size and `mining_drill_radius`, `resource_categories`, output fluidbox `pipe_connections[*].positions` per direction, pole `get_supply_area_distance()` and `get_max_wire_distance()`, beacon size and supply distance, pipe-to-ground `max_underground_distance`, and belt/underground lengths. Doing this keeps Nullius and other modded drills working.

1. **MPP's ore layout core → port to Python (MIT).** Port `layouts/simple.lua` + `layouts/common.lua`: grid convolution of ore amounts under drill footprint and mining area; enumerate every lattice offset within one drill period × 4 directions; place drills where `neighbors_inner > (size/2)^2`; score with `simple_layout_heuristic` (or `overfill_*` for leech/full coverage); postponed fill-in for unconsumed ore. Then add belt lanes per drill pair and poles on the inter-pair gap. Use `sparse`/`compact` as alternate lattice generators under the same scorer. Stdlib-only, O(tiles × area) with the separable filter.
2. **P.U.M.P. fluid pipeline → port to Python (MIT).** Trunk + branch scoring, then A* per pumpjack (farthest first), then straight-line "tunnel" connections, then prune dead ends and bury straight runs. This is the most mod-generic fluid solver (any fluid-output mining-drill) and already handles Space Age fluids, heat pipes, and foundations. Also borrow its `toolbox.lua` prototype discovery as the template for Kira's Lua export.
3. **Oil Outpost Planner's `SolveSteinerTree` → port to Python (MIT) as a general multi-terminal router.** Each terminal has alternative subtargets (the 4 pumpjack rotations); parallel BFS growth merges the closest pair repeatedly; the chosen subtarget fixes the rotation. About 500 lines of Lua. Reusable for pipes, heat pipes, and possibly belts and walls. Run it and #2 both, then keep the better plan.
4. **FactorioTools (MIT) → port strategies + use its 57-field benchmark as Kira's test oracle.** Port `ConnectedCenters` (+ FLUTE when Kira needs best-quality RSMT) and the `Snug`/FBE beacon planners; adopt the "run up to N strategies, rank by (beacon effects, beacons, pipes)" selector. Its test blueprints in `test/FactorioTools.Test/OilField/` give ready regression inputs for validating any Python port (1.1 blueprint format; positions still valid).
5. **Pole placement: greedy set-cover + bridge-join (idea from demipixel `power.js` / PlannerCore `PB_stages.lua`, re-implemented).** Place each pole on the free cell covering the most unpowered entities, then join disconnected groups by BFS over free cells in wire-reach hops. One generic stdlib routine serves ore, oil, and any later build. Implement from scratch because neither repo has a usable license (demipixel: none; PlannerCore: none).

Fallback/baseline: d4rkc0d3r's "MST over BFS distance fields + random-rotation hill-climb" (idea-only, unlicensed) is a cheap, robust second opinion for pumpjack fields and easy to write in stdlib Python.
